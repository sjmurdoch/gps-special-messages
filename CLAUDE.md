# CLAUDE.md

Project guide for Claude Code working in this repo.

This is the reproducibility companion to *Inside GNSS* (May/June 2026)
"The Empty Field That Wasn't: GPS, OTAD, and Two Decades of Encrypted
Broadcasts." It rebuilds every quantitative claim and figure in the
article from the raw GFZ navbit + NAVCEN advisory inputs.

## Orientation

Read in this order when first dropped into the repo:

- [README.md](README.md) — what the project is + quickstart.
- [REPRODUCING.md](REPRODUCING.md) — fast path (download DB, verify) and full path (rebuild from raw).
- [DATA.md](DATA.md) — provenance, citations, Zenodo DOI.
- [CLAIMS.md](CLAIMS.md) — every article footnote ↔ verifier or external citation.
- [CITATION.cff](CITATION.cff) — machine-readable citation.

## Layout (one-way DAG)

```
pipeline/   raw archives  → data/messages.duckdb
analysis/   DB            → derived tables in DB + analysis/reports/*.md
figures/    DB + reports  → figures/output/*.{png,pdf}
verify/     DB            → exit code (0 ⇔ all claims hold)
src/        the GPSSpecialMessages module (parsers, decoders, DB writer)
test/       1,041 unit tests
bin/        fetch_zenodo.sh, full_build.sh
data/       arrow_test/ committed; everything else fetched or rebuilt
```

Each bucket reads from the previous and writes to a well-known output.
Per-bucket entry points: `pipeline/run_all.sh`, `analysis/run_all.sh`,
`figures/build_all.sh`, `verify/run_all.sh`. End-to-end:
`bin/full_build.sh` chains everything; designed to run unattended
(see top of script for nohup invocation).

When a researcher asks where new code goes, follow the DAG: a new
quantitative claim → `verify/`; a new derived metric → `analysis/`; a
new chart → `figures/`; new pure helper functions → `src/` with tests.

## Adding a new claim

1. Write `verify/<claim>.jl` (≤100 lines). Follow the pattern in
   `verify/corpus_totals.jl`: read DB read-only, assert with a `check()`
   helper, exit non-zero on divergence.
2. Append it to the loop in `verify/run_all.sh`.
3. Add a row to the table in `CLAIMS.md` linking the article footnote to
   the new script.
4. Run `verify/run_all.sh data/messages.duckdb`; commit only when every
   verifier passes.

Tolerances: counts/exact totals → equality. Test statistics with random
seeds → tight numeric tolerance with the seed pinned. Plot byte-equality
is **not** verified (Cairo embeds timestamps; visual review only).

## Adding a new analysis

1. New script `analysis/<topic>.jl`. Read DB, write
   `analysis/reports/<topic>.md`.
2. Prepend the report's first line with the AUTO-GENERATED header
   (`<!-- AUTO-GENERATED by analysis/<topic>.jl on <ISO> — do not edit by hand -->`)
   so hand-written and machine-written reports stay distinguishable.
3. Hook into `analysis/run_all.sh`. Respect FK ordering: scripts that
   write child rows must run after the parents.
4. For DB writes use `INSERT ... ON CONFLICT DO NOTHING`, never
   `INSERT OR REPLACE`. REPLACE is implemented as DELETE+INSERT in
   DuckDB and breaks foreign keys from sibling correlation tables.
5. New table? Add `create_<topic>_table!(db)` in `src/duckdb_writer.jl`
   and a wipe-prelude entry in `analysis/run_all.sh` Step 0.

## Adding a new figure

1. New file `figures/figN_<name>.jl` (CairoMakie) or `.typ` (Typst).
2. Output paths must be `joinpath(@__DIR__, "output", "...")`. Emit
   PNG, PDF, and SVG.
3. Add to `figures/build_all.sh`.
4. Commit the rendered PNG + PDF + SVG outputs alongside the script.
5. CairoMakie embeds creation timestamps and font-cache ordering in PNG
   `tIME` chunks and PDF `/CreationDate` — repeated runs differ by
   ~25 bytes per output. Visually identical. Do not assert byte-equality.

## Running things

| Task | Command |
|---|---|
| Tests | `julia --project test/runtests.jl` (~30 s, expect 1,041/1,041) |
| Pipeline smoke | `julia --project pipeline/04_build_database.jl data/arrow_test/ data/test.duckdb` (~10 s, 3,710 msgs / 2 unique) |
| Fast verify | `bin/fetch_zenodo.sh messages.duckdb && verify/run_all.sh data/messages.duckdb` |
| Full unattended rebuild | `nohup bin/full_build.sh > /dev/null 2>&1 &` then `cat $WORK_DIR/_build/STATUS.md` |
| Single verifier | `julia --project verify/<name>.jl data/messages.duckdb` |
| One analysis | `julia --project analysis/<name>.jl data/messages.duckdb` |

Without `data/ops_advisories/` present the test count drops to 879/879
because the OA-parser real-data tests skip silently. Either fetch via
`bin/fetch_zenodo.sh nanu` or symlink from the source repo.

## GPS terminology gotchas

- **`prn` (1–32) ≠ `sv_id` (always 55)**. The PRN is the satellite that
  transmitted the message; the SV ID is the page identifier within
  Subframe 4. Confusing the two is the most common bug. Special
  messages always have `sv_id = 55` because that's what flags Page 17.
- **Bit positions**: APIs expose 1-indexed positions (per IS-GPS-200);
  internal code uses 0-indexed. Don't mix in the same function.
- **CP437 encoding** for the 22-byte payload. `0x00` renders as the
  Unicode replacement character.
- **Frame inversion + D30\* un-complement**: per-word, parity-checked,
  not per-byte. See `src/lnav_decoder.jl` for the principled approach
  (try parity, retry with un-complement, use whichever passes).

For the underlying GPS context see DATA.md and the article. For
deeper detail see IS-GPS-200N §20.3.3.5.1.8 (linked from DATA.md).

## Performance hot paths

- Arrow column views (`row.navbits`) are zero-copy `SubArray{UInt8}`.
  Always **filter before materialising** — `collect()` then `filter`
  costs ~1000× more allocations than `filter` then `collect()`.
- `_add_bits_to_buffer!` in `src/lnav_decoder.jl` must stay top-level
  (not a closure) for type stability. Verify with `@code_warntype`
  after edits.
- For parallel DB writes use `parallel_processor_threaded.jl` with the
  parallel-collect-then-serial-write pattern. **Never share a DuckDB
  connection across threads** — corrupts the WAL.
- After bit-extraction edits, profile a million-row run; allocation
  count should stay in the low tens of thousands, not millions.

## Pitfalls (each one bit the codebase)

- **Null bytes in DuckDB VARCHARs crash the C API.** Use
  `sanitize_ascii_message()` or substitute a visible placeholder. Be
  especially careful when porting Python (`str(None)` → `"None"` is a
  4-char string; a Julia null byte is a real null).
- **`save_nanu_records!` and FK cycles.** Re-running the analysis used
  to trip a foreign-key constraint (REPLACE = DELETE+INSERT). Pattern
  is now `INSERT ... ON CONFLICT DO NOTHING`. Don't switch back.
- **Non-deterministic secondary sort** in
  `analysis/behavioral_changes.jl` (`sort!(sub, :detected_at)` doesn't
  break ties). Top-N slices on dates with many shared timestamps will
  vary across runs. Fix when changing nearby code: add `[:detected_at, :prn]`.
- **`marginal_entropy_ppm.md` line layout is load-bearing.**
  `figures/fig2_entropy_distribution.jl` parses the sorted-results code
  block via regex. If you change the column layout, update the regex.
- **`pipeline/04_build_database.jl` row count must equal 12,163,006**
  (3,994 unique). If a refactor changes either count, the article and
  every verifier are wrong; investigate before "fixing the test."

## What does not belong in this repo

- Working notes, plans, slide decks, draft articles. The repo is
  user-facing reproducibility; chronology lives in commit history.
- Full `data/raw/`, `data/processed/`, `data/arrow/`, or
  `data/messages.duckdb`. Gitignored; fetched from Zenodo or rebuilt.
- The article PDF, Tyley 2015 briefing, IS-GPS-200/240 reference
  documents. All cited via DATA.md, never vendored.
- Generic-overview analysis scripts that don't back an article claim.
  If a claim isn't in `CLAIMS.md`, either add it or drop the script.

## Conventions worth keeping

- Numeric prefixes only where order matters: `pipeline/0X_*` and
  `figures/figN_*`. No category prefix when the directory implies it.
- Output filenames are semantic, not numeric (`lnav_schematic.png`,
  not `fig1.png`) — the article cites them by name.
- `Manifest.toml` is committed (not the Julia template default) for
  exact dependency pinning.
- Reports drop the `_report` suffix in `analysis/reports/`.
